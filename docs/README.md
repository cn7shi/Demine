## 留档边界

这些文件记录可核查的实现说明、选择理由、代码入口和测试结果。开发履历按有意义的交付批次维护，不声称逐条记录所有编辑操作；早期条目依据已有交付材料整理。

源码注释解释局部约束，关键逻辑文档解释跨模块行为，决策记录解释取舍。真实私人对话与执行日志保存在 Git 忽略的本地目录，不直接复制进工程档案。

## 维护方式

实现记录、逻辑说明和测试记录描述当前状态；开发履历保存阶段变化；决策发生改变时追加新条目并标明所替代的旧选择。每批交付串联“改动 → 原因 → 逻辑 → 验证”，共享细节使用链接，避免几份文档分别维护相同长段落。
