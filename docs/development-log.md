## DEV-001 · 自动采集与时间线原型

日期：2026-10-05。状态：最终实现连同 DEV-002 修复共同收录于本地基线 `b3ff2ac`；本阶段没有单独提交。

**需求**：接入后自动观察 Agent 工作，让人能够展开查看被完成回复略过的尝试与反馈。

**代码与结果**：

| 修改位置 | 实现内容 |
| --- | --- |
| `src/main.rs`、`src/server.rs` | 指定项目启动、单次扫描、持续服务、只读本机接口 |
| `src/collector.rs` | 项目归属校验、发现来源、完整行读取、增量续读、来源变化识别 |
| `src/adapter.rs`、`src/store.rs` | 格式适配、行级证据、事件更新、事务与读取进度 |
| `web/src/app.ts`、`web/public/` | 会话列表、可展开时间线、原始证据、筛选、分页、实时更新 |
| `tests/`、`scripts/`、CI 配置 | 合成来源、后端与浏览器测试、Windows/Linux 检查配置 |
| `AGENTS.md`、`docs/`、`README.md` | 工程规范、范围、决策、使用方式与验证记录 |

**主要原因**：先建立可靠证据，再做经验解释；采用本地只读采集和 SQLite 原子提交。具体取舍见 [ADR-001 至 ADR-007](decisions.md)。

**当时的验证**：22 项 Rust 测试、4 项浏览器测试通过；真实接入匹配 3 个来源，首次保存 291 条记录，紧接着重扫新增 0。此为该批次历史结果，不覆盖后续发现。

**后续修正**：DEV-002 审查发现原实现仍有五项缺陷。测试通过并不意味着已覆盖所有场景；失败条件和回归见下一批。

## DEV-002 · OCR 委托自查与修复

日期：2026-10-05。状态：已修复并实测，收录于本地基线 `b3ff2ac`；没有伪造修复前的阶段提交。

**需求**：使用 Alibaba OpenCodeReview 检查首版。实际采用委托模式，由工具提供清单与规则，由本对话助手审查，未额外调用另一模型。

| 问题与变更 | 代码位置 | 理由/证据 |
| --- | --- | --- |
| 压缩内部字段改为白名单；旧库迁移至模式 2 | `src/adapter.rs`、`src/store.rs` | [R1](ocr-review.md)、ADR-008；不能只修未来输入而留下既有问题数据 |
| 历史页边界独立保存 | `web/src/app.ts` | [R2](ocr-review.md)、ADR-009；迟到的旧事件不代表中间历史已加载 |
| 合并条目时比较修订号 | `web/src/app.ts` | [R3](ocr-review.md)、ADR-009；旧响应不能覆盖新状态 |
| 原生明确失败无退出码也保留 | `src/adapter.rs` | [R4](ocr-review.md)、ADR-010；启动失败可能没有退出码 |
| 单次扫描错误返回非零退出码 | `src/main.rs` | [R5](ocr-review.md)、ADR-010；脚本需要准确区分扫描成败 |

**验证**：增加 4 项 Rust 和 2 项浏览器回归用例，先在原实现上复现失败，再验证修复；总计 26 项 Rust、6 项浏览器测试通过。真实数据库完成迁移，禁止字段检查为 0，采集恢复正常。详见 [测试记录](testing.md)。

**已知剩余**：尚无独立第二审查者的复核；云端 CI、Linux 实测和大规模日志性能尚未验证；CI 第三方 Action 固定版本与任务超时留待发布前处理。
