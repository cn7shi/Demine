# Gotcha Memory

## 1. 我们是什么？

**开发者的“隐性工程经验沉淀外脑”**

——专门捕获你在与 AI 协作中被跳过的暗坑与限制，并将其沉淀为个人工程知识。

---

## 2. 为什么做这个？

* **随着 AI 接管越来越多的执行工作，开发者正从执行者转向决策者。**
* **AI 在执行过程中，会自动消化大量原本可以沉淀为工程经验的摩擦、缺失与修正。** 尤其在长程对话与复杂调试中，AI 经历多次方案尝试、报错与边界拉扯后最终解决的问题，其中的工程暗坑与限制往往随着对话结束而被淹没，未能自然进入开发者的认知。
* **决策和工程经验的积累并不等价**：架构、抽象等决策相对容易学习，而工程中的暗坑、边界条件和现实约束，往往只能在执行和试错中沉淀。
* **而当下的工程仍然不是完全可被 AI 解决的**：很多时候，我们做不出来，并不是不会，而是不知道有这样的解法、限制或坑。

---

## 3. 面向谁？

**希望在与 AI 结对编程中沉淀自身工程经验，建立个人工程知识库的开发者。**

---

## 4. 我们做了什么？

* **记录场景与排雷轨迹**  
  记录 AI 协作中实际遇到的问题。尤其在长程对话与多轮排错中，还原 AI 从方案尝试、报错受挫到最终解决问题的试错轨迹，提炼其中“为什么前几种解法行不通”的经验。

* **结构化沉淀**  
  将一次具体经历整理成结构化文档，在解释问题的同时，保留个人补充、理解和复盘的空间，而不是直接生成一份“标准答案”。

* **归类与建立索引**  
  根据技术领域、问题类型、底层原因等维度进行归类，逐步形成个人工程知识库。

* **适当引申与追问**  
  基于当前经验进行有限的关联、延伸与追问，帮助用户发现其中值得进一步理解的部分，而不是替用户完成全部思考。
